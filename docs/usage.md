# StickS3 摩斯电码翻译器 · 使用说明

用 G11 按键手敲摩斯电码，屏幕实时翻译成拉丁字母与数字；G12 按键负责辅助操作。

> **当前验证状态**：固件已烧进板子，写入 hash 校验通过（`Wrote 615168 bytes ... Hash of data verified`）。
> 解码内核的 11 项上位机仿真全部通过，但**真机上的屏幕表现和串口控制台还没有一次成功观测**
> （烧完探串口时 `w` 无响应、8 秒无输出）。下面描述的是代码实际实现的行为，
> 不是已经被真机证实的行为。第一次上机请对照第 8 节逐项确认。

---

## 1. 两个键的分工

| 键 | GPIO | 作用 |
|---|---|---|
| KEY1（正面大键） | G11 | 摩斯键（straight key）。按下=发声，松开=间隙 |
| KEY2（侧面小键） | G12 | 辅助手势：退格 / 练习 / 静音 / 减速 / 清行 |

侧面电源键不可编程，只用于开机和长按进下载模式。

敲击时**点与划的区别只在按住时长**，不是"快按 vs 慢按两种按法"——一次按下就一个符号。

---

## 2. 时间判据

记一个"点"的长度为 `u`（单位时长），当前判据是：

| 判定 | 阈值 | `u=100ms` 时的实际值 |
|---|---|---|
| 点 `·` | 按下 < 1.6 `u` | < 160ms |
| 划 `−` | 按下 > 2.4 `u` | > 240ms |
| 模糊区 | 1.6–2.4 `u` 之间 | 沿用你上一个符号的手型 |
| 字母边界 | 间隙 ≥ 2 `u` | ≥ 200ms |
| 单词边界（打空格） | 间隙 ≥ 5 `u` | ≥ 500ms |
| 走神复位 | 间隙 ≥ 10 `u` | ≥ 1s，只复位状态不吞内容 |

标准摩斯要求间隙 3 `u` / 7 `u`，这里放宽到 2 `u` / 5 `u`，因为手敲的间隙普遍比电键短。

`u` 的有效范围 40ms–400ms，对应约 30 WPM 到 3 WPM。

---

## 3. 怎么敲

1. 短按一下 → 屏幕出现 `·`
2. 长按再松 → 屏幕出现 `−`
3. 停一下（≥2 单位）→ 该串符号提交成一个字母，进入正文行
4. 停久一点（≥5 单位）→ 自动补一个空格，开始下一个单词
5. 敲错了 → 连打 **7 个点**（`.......`）会撤销上一个字符；或者单击一次 KEY2

不用等屏幕提交才敲下一个字母：判定用的是事件自己的时间戳，不是程序处理到的时刻，
所以屏幕刷新、存参数这些耗时不会影响判定的正确性。

---

## 4. 屏幕怎么看（240×135 横屏，8×16 点阵字）

从上到下六行：

```
M u100 12.0w* B85          ← 状态行
 · − · −        ▐███▌      ← 符号区 + 实时按下进度条
 ELMST?                    ← 剩余候选
 HELLO WORLD               ← 正文行（大号字）
 PREVIOUS LINE             ← 上一行（小号灰）
 12c 1e K1 key K2 gest     ← 计数与提示
 ERR  7dots=back           ← 警示行
```

**状态行**
- `M` = 常规模式，`T` = 练习模式
- `u100` = 当前单位时长 100ms
- `12.0w` = 折算速率（1200 / u）
- 末尾 `*` = 自适应开启
- `B85` = 电量 85%，低于 20% 整行变红

**符号区**：点画成圆、划画成方块，**长度按判据比例画**，所以图上就能看出你这两下会被判成什么。
当前前缀在码表里走不通时变红，而不是静默丢弃。

**进度条**（右上角）：实时反映"这一下按了多久"。绿色=已可判为点，蓝色=已可判为划，
琥珀=落在模糊区，红=已出错。条上两根细刻度线就是 1.6u 和 2.4u 的位置，调参时一眼能看出阈值该往哪挪。

**候选行**：还没打完时列出所有还可能成立的字母，例如 `·` 打完显示 `ABCDEFGHI?`；
练习模式下这行换成 `TGT K 12/1`（目标字母 + 命中/失误）。

**警示行**：`ERR 7dots=back` / `MISS` / `OVF<次数>`（事件队列溢出）/ `KN wait` / `SK end`。

## 5. KEY2 手势

| 操作 | 效果 |
|---|---|
| 单击 | 退格（删掉上一个字符） |
| 双击 | 开/关练习模式 |
| 三击 | 开/关回听音（sidetone） |
| 四击及以上 | 单位时长 +10%，即"减速"校准 |
| 按住 ≥0.6 秒后松开 | 清空当前行 |

多击之间的间隔窗口是 450ms。**单击退格有约 450ms 的固有延迟**——这是必须等一等才能区分"一次"和"两次"的代价，用两个物理键换掉了第三个键。
想立即撤销，用 7 个点更干脆（它走摩斯路径，不等手势窗口）。

注意：按键手势只有"减速"，没有"加速"。要往快调请用串口 `u <ms>`。

---

## 6. 支持的字集

- 26 个大写字母 A–Z
- 10 个数字 0–9
- 标点 `.` `,` `?` `/` `(` `)`
- 专业符（当按键用）：

| 符号 | 码 | 作用 |
|---|---|---|
| BT | `-...-` | 字段分隔 → 打一个空格 |
| AR | `.-.-.` | 报文结束 → 换行并导出整行 |
| KN | `-.--.` | 交给对方 → 屏幕显示 `KN wait` |
| SK | `...--.` | 通联结束 → 屏幕显示 `SK end` |
| — | `.......` | 错误信号 → 退格 |

两处历史撞码，本表让位给更常用的：`AR` 与 `+` 同为 `.-.-.`，`=` 与 `B` 同为 `-...`，
因此不提供 `+` 和 `=`。

超过 8 个符号的组合视为非法，屏幕显式打 `?` 并计入错误数，不会静默丢。

## 7. 手速自适应（默认开启）

不用手动配速：程序从你敲的**按下时长**里反推 `u`。

- 观察最近 16 次按下，把它们排成一维序列，在最大相邻间隙处切两簇（点簇 / 划簇），两侧至少各 2 个样本才接受
- 只有当"划簇均值 / 点簇均值"落在 2.2–4.2 之间才认为这个切法有意义（理论上应当接近 3）
- 只在**单词边界**更新，避免敲到一半改判据
- 更新用 `u = (当前u + 新估计)/2` 平滑，不是直接跳变
- 符号比例法失败时退回"间隙均值"估计；连续拒绝 8 次才放弃自适应
- 手动改过（手势或串口 `u`）之后自适应自动关闭，可用 `a` 重新打开

仿真验证：手速从 60ms 漂到 220ms，`u` 收敛到 220ms，整句识别 93.0% 正确；
带 ±25% 抖动时 100% 正确。

## 8. 第一次上机的确认清单

按顺序做，任何一步不对就停下来告诉我现象：

1. 屏幕是否点亮、是否显示上面第 4 节那六行
2. 短按 KEY1：符号区出现一个圆点，进度条走绿
3. 长按 KEY1：出现方块，进度条走蓝
4. 敲 `....` 停一下：正文行出现 `H`
5. 敲 `---`：出现 `M`
6. 敲一个非法组合（比如 `-` 后紧跟超长串）：变红或出 `?`
7. KEY2 单击：上一字符消失（约 0.45s 后）
8. KEY2 三击：回听音开关，扬声器有无变化
9. 串口敲 `w` 回车：应回一行 `u=... wpm=... chars=... err=... hit=... miss=... ovr=...`

第 9 步是现在唯一没跑通的环节，也是我最怀疑的地方。

## 9. 串口控制台

插上 USB 后用 115200 打开（原生 USB-CDC，不是 UART 桥，所以插上线就有口）：

```
python -m platformio device monitor
```

| 命令 | 作用 |
|---|---|
| `u <ms>` | 设定单位时长（毫秒），同时关闭自适应 |
| `a` | 自适应开关 |
| `s` | 回听音开关 |
| `v <百分比>` | 音量 |
| `t` | 练习模式开关 |
| `e` / `c` / `n` | 退格 / 清行 / 换行 |
| `d` | 把全文导出到串口 |
| `w` | 打印统计 |
| 其它任意 | 打印帮助 |

控制台命令只在事件队列空闲时轮询，不会抢占敲击判定。

配置（单位时长、自适应、回听音、音量）存在 NVS 的 `morse` 命名空间里，
写在 UI 任务里完成，所以存参数的闪存耗时不会拖慢解码。断电保留。

## 10. 练习模式

双击 KEY2 进入。屏幕给出一个随机目标字母（`TGT K`），你敲它：
- 敲对 → `hits` +1，连续命中数累加
- 敲错 → `misses` +1，警示行亮 `MISS`，记下来哪个字母错了

统计行在候选行位置显示 `TGT K 12/1`（命中/失误）。这模式不改动解码逻辑，只是把"你该敲什么"这件事替你决定。

---

## 11. 使用注意与已知现象

- **别用充电线**：StickS3 走 ESP32-S3 原生 USB，纯供电线会出现"屏幕亮但电脑完全没反应"，本项目已实测踩过。
- **回听音跟着手走**：按下即刻响、松开即刻停，用扬声器而不是蜂鸣器，音量 `v` 可调。
- **60 秒无操作**屏幕自动调暗，敲一下恢复。
- **抖动处理**：松开后 3ms 内的按下沿被丢弃，松开沿永远放行，所以不会出现"卡键"；短于 4ms 的脉冲当毛刺忽略。
- **漏沿补偿**：中断被长期屏蔽时，定时器会读实际电平把漏掉的边沿补上，键不会悬在半按状态。
- **`OVF` 计数非零**说明事件队列（64 深）溢出过，此时判定可能有缺口——通常只在 UI 被长时间阻塞时出现。
- 正文行缓冲 768 字节，超出后从最早的内容开始丢。
- 电量 250mAh：轻载实测约 52µA、中载约 102µA、满载约 519mA。长时间连续敲按满载估算可用不到半天，纯待机可放很久。

## 12. 编译与烧录

```
python -m platformio run -e sticks3              # 编译
python -m platformio run -e sticks3 -t upload    # 烧录（走 COM 口）
python -m platformio run -e sticks3 -t erase     # 整片擦除，回到空板
```

上位机仿真（不需要板子，改内核后必跑）：

```
g++ -std=c++17 -Wall -Wextra -O1 -o tools/hosttest/hosttest.exe src/core/*.cpp tools/hosttest/main_test.cpp
tools/hosttest/hosttest.exe
```

`src/core/` 不含任何 Arduino 依赖，可以单独在电脑上编译测试；硬件相关全部隔离在 `src/firmware/`。
